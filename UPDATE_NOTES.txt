CHANGE 1: Fix FUH & Academic Unit pickers (adminProvisioning + assignableRoleManager)
---------------------------------------------------------------------------------------
Files: presentation/adminProvisioning.pmd
       presentation/assignableRoleManager.pmd

Problem:
  - fuhPicker and academicUnitPicker instanceList fields were using onSearch
    with event.query filtering — this pattern is not supported in these pages
    and returned no results when typing.
  - After switching to static `values` expressions, fuhPicker had a FATAL
    duplicate `values` property (old empty [] not removed).

Fix Applied:
  - Removed `"values": "<% [] %>"` (old placeholder) from fuhPicker in both files.
  - Moved the correct expression `"values": "<% customOrganizationsFUH.data.map(...) %>"`
    to the standard position (right after `required`, before `onChange`).
  - academicUnitPicker already had correct single `values` — no change needed.
  - Removed all onSearch handlers from both pickers.

Result: Both pickers now pre-load their options from WQL endpoint data at page
load (same pattern used throughout the rest of the codebase).

DEPLOYMENT NOTE
---------------
GitHub Actions deploy requires a valid WD_DEV_TOKEN (PKCE token, ~8h TTL).
Previous runs #182 and #183 failed due to expired token.

To refresh:
  1. Run `wdcli app deploy` interactively on your local machine
  2. Copy wcpTenantAccessToken → ubc_wcpdev2 from ~/.wdcli/config.json (or equivalent)
  3. Update the WD_DEV_TOKEN secret in GitHub repo Settings → Secrets → Actions
  4. Re-run the failed workflow OR push a new commit to trigger deploy
